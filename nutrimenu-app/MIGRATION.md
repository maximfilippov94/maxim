## Чего в мобильном ещё нет

Отсортировано по весу в продукте.

1. **Анкеты и подписка EQUA AI** — опросы по питанию и тренировкам,
   покупка набора, еженедельная адаптация, промокоды (`/client/ai*`).
   Сам чат с моделью уже работает.
2. **Женское здоровье** — сделано. Не перенесены только настройки цикла
   (`/client/health/cycle/settings`) и ответы на вопросы о прогнозе.
3. **Добавление еды** — переработанный в вебе bottom sheet: поиск, камера,
   штрихкод, свой продукт, несколько продуктов в один приём.
4. **Список покупок** — период, прогресс, категории, свои продукты дома,
   сброс (`/client/shopping*`, `/client/home-products`).
5. **Тренировки** — пары фото упражнения, подходы, вес и повторы, расход.
6. **Быстрый check-in** — энергия, настроение, дискомфорт, аппетит.
7. **Прогресс** — графики веса, КБЖУ, воды, выполнения.

## Риски, которые надо решить до написания экранов

- **Стриминг AI.** Проверить, отдаёт ли `POST /client/ai` поток. `fetch` в
  React Native не читает тело по частям без доработки — если потока нет,
  typing-состояние строится на опросе, а «Остановить» отменяет запрос через
  `AbortController` (в клиенте это уже поддержано полем `signal`).
- **Разрешения камеры.** Для штрихкода нужен сценарий отказа: в вебе его нет.
- **Клавиатура в чате.** Composer снизу вместе с доком и безопасной зоной —
  обычный источник наложений.
- **Перенос расчётов.** Пересчёт КБЖУ, порций и замен в вебе размазан по
  `app.js`. В мобильном вынести в отдельный модуль, а не повторять россыпь.

## Порядок работ

### Поправка к карте API

В первом отчёте было 367 маршрутов. Разбор пропустил три, записанных с
другим порядком условий: `/client/checkin`, `/client/connect` и
`/client/connect-code`. Все три в мобильном уже используются —
недельный чек-ин и подключение специалиста по коду работают.

Маршрут `GET /client/checkin` (последние четыре отчёта) не читает ни
веб, ни приложение — отчёт только отправляют. Не додумываю экран, которого
нет в вебе; отмечаю как возможность.

Этапы 1–11 закрыты (аудит, архитектура, авторизация, «Сегодня», «Неделя»,
еда и штрихкод, покупки, чаты, тренировки, женское здоровье). Дальше:
нативная полировка.

Из кабинета специалиста остались не перенесёнными: продвижение
(`/specialist/promotion`) и заявки на профессию. Отдельный маршрут
`/specialist/signals` переносить незачем: главная уже показывает
«Требуют внимания» из `attention` дашборда, с теми же причинами.
У клиента: свои анализы, лекарства и аллергии (смотреть можно, добавлять
нельзя), продукты дома, промокод, цель по воде, настройки цикла.

Push закрыт целиком: разрешение, токен Expo, канал Android, отписка при
выходе и переход по нажатию. Переход ведёт туда, где сервер положил
адрес экрана приложения в `data.screen` — седьмой аргумент `pushSend`,
а он задан только у звонков. Остальные уведомления открывают главную;
доделывать это надо на сервере, не в приложении.

Платежи приложение не проводит сознательно (так просило ТЗ). Пока
`payments_mode` на сервере равен `off`, набор EQUA AI подключается
бесплатно и путь работает целиком; при `live` экран говорит, что
оформить нужно на сайте, и не открывает платёжную страницу — внешняя
оплата внутри приложения это ещё и повод для отказа в App Store.

Стриминга у AI нет: чат идёт через `/client/messages`, сервер синхронно
спрашивает модель и возвращает готовый ответ. «Печатает…» — локальное
состояние, «Остановить» — отмена запроса, которую клиент уже умеет.

Платежи не подключаются: ЮKassa, покупки App Store и Google Play отложены,
экраны подписки остаются только для чтения.
