# EQUA — мобильное приложение

React Native + Expo (SDK 57). Говорит с тем же бэкендом, что и веб-версия:
ни один эндпоинт не менялся, база не трогалась.

---

## 1. Что нужно поставить один раз

| Что | Зачем | Как проверить |
|---|---|---|
| **Node.js 20 или новее** | на нём работает сборщик | `node -v` |
| **Expo Go** на телефоне | им открывается приложение | App Store / Google Play |

Аккаунт разработчика Apple на этом шаге **не нужен**. Проверено на Node 22.22.

---

## 2. Первый запуск

Распакуйте архив и в его папке выполните:

```bash
npm install
```

Ставится минут пять, дальше не повторяется.

---

## 3. Запуск на телефоне

Телефон и компьютер должны быть **в одной сети Wi-Fi** — иначе телефон
не увидит сборщик.

```bash
npx expo start
```

Боевой адрес `https://nutrimenu.ru` уже прописан в приложении по
умолчанию — переменную задавать не нужно. В терминале появится QR-код.

* **iPhone** — откройте камеру, наведите на код, нажмите на подсказку.
* **Android** — откройте Expo Go и отсканируйте код внутри приложения.

Вход — обычной учётной записью с сайта.
Демо-специалист: `demo@nutrimenu.local` / `password`.
Демо-клиент: `anna@demo.local` / `password`.

### Другой сервер

`EXPO_PUBLIC_API_BASE` — единственная настройка, которая переключает
приложение между серверами:

```bash
EXPO_PUBLIC_API_BASE=https://другой-домен npx expo start
```

Адрес по `http://` в Expo Go обычно проходит, но **в собственной сборке
(шаг 5) — нет**: iOS по умолчанию запрещает незащищённые запросы.
Поэтому боевой домен и должен быть с сертификатом.

### Локальный бэкенд вместо боевого

Если удобнее гонять на своей машине, поднимите PHP-сервер веб-проекта
и укажите **адрес компьютера в сети**, а не `127.0.0.1` — телефон под
`localhost` понимает сам себя:

```bash
# в папке веб-проекта
php -S 0.0.0.0:8201 _router.php

# в папке приложения, где 192.168.1.50 — IP компьютера
EXPO_PUBLIC_API_BASE=http://192.168.1.50:8201 npx expo start
```

IP компьютера: `ipconfig getifaddr en0` на macOS, `ip addr` на Linux,
`ipconfig` на Windows.

## 3а. Запуск без своего компьютера (GitHub Codespaces)

Если на вашей машине не встаёт Node — например, macOS старее Big Sur —
сервер можно поднять в облаке. Компьютеру от вас нужен только браузер.

1. Откройте репозиторий на GitHub → зелёная кнопка **Code** → вкладка
   **Codespaces** → **Create codespace on …**. В браузере откроется среда
   разработки; `npm install` выполнится сам (это прописано в
   `.devcontainer/devcontainer.json` в корне репозитория).

2. Когда внизу появится терминал, войдите в свой аккаунт Expo:

   ```bash
   cd nutrimenu-app
   npx expo login
   ```

   Это нужно, если в Expo Go на телефоне вы тоже вошли в аккаунт: иначе
   он сочтёт проект чужим и откажется его открывать. Вход сохраняется
   только внутри этой среды — в новом Codespace повторить.

3. Запустите сервер:

   ```bash
   EXPO_UNSTABLE_TUNNEL_V2=1 npx expo start --tunnel
   ```

   `--tunnel` обязателен: телефон и облако не в одной сети, и обычный
   QR-код с локальным адресом ему не подойдёт. `EXPO_UNSTABLE_TUNNEL_V2`
   включает туннель, который уже лежит в зависимостях (`@expo/ws-tunnel`),
   — без него Expo попросит доставить `@expo/ngrok`.

   Пробрасывать порт 8081 руками не нужно и не помогает: Codespaces
   отдаёт по такому адресу свою страницу входа, и Expo Go спотыкается
   о неё сообщением «Failed to parse manifest JSON».

4. Появится QR-код. Наведите камеру iPhone, откройте в **Expo Go**.
   Общий Wi-Fi не нужен — работает и с мобильного интернета.

   Expo Go должен быть свежий: старая версия скажет «Project is
   incompatible with this version of Expo Go» — обновите его в App Store.

Пока вкладка Codespaces открыта, сервер живёт. Закроете — остановится,
телефон отвалится; открыть заново и повторить шаг 3.

Бесплатного лимита Codespaces (около 60 часов в месяц на личный аккаунт)
на тестирование хватает с запасом. Не забывайте останавливать среду
кнопкой **Stop codespace**, когда закончили, — иначе часы капают.

## 4. Проверка в браузере

```bash
EXPO_PUBLIC_API_BASE=http://127.0.0.1:8201 npx expo start --web
```

Откроется `http://localhost:8081`. Логика, данные и вёрстка проверяются
полностью; чего в браузере не увидеть — сказано в разделе 7.

Локальному бэкенду для этого нужен CORS: он уже есть в `_router.php`
веб-проекта, который в боевой архив не попадает. Нативному приложению
CORS не нужен вовсе.

## 5. Сборка без Mac

Через сервис EAS — собирает у себя, старый Xcode не нужен.

```bash
npm i -g eas-cli
eas login
eas build --platform android --profile preview   # APK, раздаётся ссылкой
eas build --platform ios --profile preview       # нужен Apple Developer, 99 $/год
eas submit --platform ios                        # выложить в TestFlight
```

Профили в `eas.json`:
`development` — с нативными модулями для отладки,
`preview` — для тестировщиков, `production` — для магазинов.

Для раздачи нутрициологам: Android-APK — сразу ссылкой, без аккаунтов;
iOS — только через TestFlight, а значит через платный Apple Developer.

## 6. Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| QR не открывается, «не удалось подключиться» | телефон в другой сети или в гостевом Wi-Fi с изоляцией клиентов |
| Приложение открылось, но «Нет связи с сервером» | неверный `EXPO_PUBLIC_API_BASE`: с телефона `127.0.0.1` — это сам телефон |
| Экран не обновляется после правки файла | сборщик запущен с `CI=1` — в этом режиме слежение за файлами выключено, перезапустите без него |
| Сборщик не стартует, ошибки про `api.expo.dev` | нет доступа к интернету у сборщика; запустите с `EXPO_OFFLINE=1` |
| Странные ошибки после обновления пакетов | `rm -rf node_modules && npm install`, затем `npx expo start --clear` |

Проверить типы перед сборкой: `npm run typecheck`.

## 7. Что видно только на устройстве

В браузере не проверяются и не эмулируются:

* настоящее **Liquid Glass** (iOS 26) в таб-баре и кнопке «+» — в браузере
  вместо него размытие;
* **SF Symbols** — на iOS иконки системные, в браузере нарисованы контуром;
* **тактильная отдача** при переключении вкладок, отметке блюда, сохранении веса;
* системная **шторка** «Записать вес» с фиксаторами высоты — в браузере это
  обычный экран;
* **сетчатый градиент** на экране входа — в браузере линейный;
* покадровое следование линзы таб-бара за пальцем при листании.

## 8. Что где лежит

```
app/                    экраны, маршрут = имя файла (expo-router)
  _layout.tsx           корень: провайдер темы и сессии, стек экранов
  index.tsx             развилка: вход или кабинет
  login.tsx             вход
  client/index.tsx      кабинет: листание страниц + таб-бар + кнопка «+»
  weight.tsx            шторка «Записать вес»
  progress.tsx          ─┐
  shopping.tsx           ├─ разделы из «Ещё», тонкие обёртки над src/screens
  services.tsx          ─┘
src/
  theme.ts              палитры «Тёмно-синяя» и «Фарфор», шкалы отступов
  api.ts                клиент к /api/v1, токен, типы ответов
  store.tsx             контекст темы и сессии
  format.ts             числа, склонения, рубли
  haptics.ts            тактильная отдача одним словарём
  screens/              Today, More, Shopping, Progress, Services
  ui/                   Card, Btn, Bar, Icon, Glass, TabBar, Pager, List, NavBar
```

Файлы вида `Pager.native.tsx` / `Pager.web.tsx` — одно и то же для телефона
и браузера: у части нативных пакетов веб-реализации нет, и сборщик сам
выбирает нужный по платформе.

## 9. Что уже работает

* вход по реальной учётке, токен хранится на устройстве;
* «Сегодня»: калории, макросы, вес, отмечено, приёмы пищи по группам;
* отметка «съедено» — мгновенно, с откатом при обрыве сети;
* «Ещё» списком во всю ширину: «Прогресс и замеры», «Список покупок»,
  «Услуги и цены» — все на живых данных;
* галочки в списке покупок сохраняются на сервере и видны на другом устройстве;
* переключение темы: тёмная, светлая, как в системе;
* листание страниц пальцем, линза таб-бара едет за жестом.

## 10. Push-уведомления

Код написан целиком: после входа приложение спрашивает разрешение, отдаёт
серверу токен, а по нажатию на уведомление открывает нужный экран. Но
**в Expo Go они не приходят** — Expo убрал удалённые уведомления оттуда
начиная с SDK 53. Чтобы включить их по-настоящему, нужно три шага:

```bash
npx eas init          # заведёт проект и допишет extra.eas.projectId в app.json
npx eas credentials   # APNs-ключ для iOS, ключ Firebase для Android
npx eas build --profile development --platform ios
```

Ключи APNs берутся в аккаунте разработчика Apple ($99/год), ключ Firebase —
бесплатно. Пока этого нет, приложение честно пишет в разделе «Уведомления»,
почему они молчат, — и ничего не ломает.

## 11. Что происходит при плохой связи

Запросы, которые ничего не создают (GET, а также PUT и DELETE), при
обрыве или ответе «сервер занят» (429, 502, 503, 504) повторяются сами:
две дополнительные попытки с паузами 0,4 и 1,4 с. POST не повторяется —
отправленное сообщение или пост могли дойти до сервера в момент обрыва,
и вторая попытка их бы задвоила; там, где повтор заведомо безопасен,
его включают явно: `api(path, { method: 'POST', retry: true })`.

Зависшее соединение не держит экран бесконечно: у попытки есть свой
предел в 12 секунд, у всего запроса — общий потолок 25 секунд, после
чего приложение говорит «нет связи», а не крутит загрузку.
