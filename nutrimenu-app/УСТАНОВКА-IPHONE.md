# Как поставить EQUA на свой iPhone

Два пути. Если Mac свежий и на нём есть Xcode 26 — шаги 1–6 ниже,
бесплатным Apple ID. Если Mac старый (2012–2015, macOS ниже Sequoia) —
сразу следующий раздел: сборку делает облако, Mac не участвует.

Шаги 1–6 — для случая, когда есть Mac с Xcode 26, а платного аккаунта
Apple (99 $) пока нет. Такая сборка ставится обычным Apple ID и живёт **7
дней** — после этого приложение перестаёт открываться, и его нужно
залить заново тем же способом (данные внутри не теряются, вход
сохраняется).

Что в такой сборке работает: всё, кроме **входящих уведомлений с
сервера** — бесплатная подпись их не умеет. Видеозвонки, камера,
сканер штрихкодов, фото блюд, документы — работают.

---

## Сначала — быстрый путь без Xcode: Expo Go

Если нужно просто посмотреть приложение на своём iPhone сегодня, Xcode
не нужен вовсе. Поставьте **Expo Go** из App Store и дальше:

```bash
cd nutrimenu-app
npm install
npx expo start --go
```

В терминале появится QR-код. На iPhone открыть **Камеру** и навести на
него — предложит открыть в Expo Go. Телефон и компьютер должны быть в
одной сети Wi-Fi; если сеть не пускает (гостевая, корпоративная) —
`npx expo start --go --tunnel`, медленнее, но работает через интернет.

Флаг `--go` нужен потому, что в проекте стоит `expo-dev-client`: без
флага `npx expo start` ждёт свою сборку. То же самое делает клавиша
**`s`** в уже запущенном терминале — она переключает между Expo Go и
своей сборкой.

**Что в Expo Go работает:** вход, меню, дневник, сканер штрихкодов,
снимки блюд, документы, тренировки, переписка, оплата — всё, кроме
одного.

**Чего нет:** видеозвонков. Их нативная часть (`react-native-webrtc`)
в Expo Go не входит — это сторонний модуль, а Expo Go несёт только то,
что Expo положил в него заранее. Приложение это знает: кнопка звонка в
шапке переписки не показывается, входящие не приходят, ничего не
падает. Проверить звонки можно только в своей сборке — ниже.

**Чего ещё нет:** уведомлений с сервера. Их убрали из Expo Go начиная с
SDK 53, и в терминале будет предупреждение от `expo-notifications` —
это ожидаемо, не ошибка.

## Если Mac старый — сборку делает облако, а не он

MacBook 2012 года — это максимум macOS Catalina, а на ней Xcode не выше
12-го. Xcode 26 туда не встанет никогда, и локальная сборка отпадает
совсем. Шаги 1–6 ниже для этого случая не годятся.

**Но свой Mac для сборки под iPhone и не нужен.** EAS собирает проект на
своих машинах, с нужным Xcode; ваш компьютер только отправляет команду —
подойдёт и Catalina, и вообще не Mac.

Что потребуется: **Apple Developer Program, 99 $ в год**. Это не про
способ сборки, а про подпись: без платного аккаунта Apple не выдаёт
профиль, в котором указан ваш телефон, и любая сборка — хоть из облака,
хоть с Xcode — на устройство не встанет. Бесплатный Apple ID работает
только когда Xcode собирает и ставит приложение сам, по кабелю, а этого
пути у вас нет.

Порядок после оплаты:

```bash
npm install -g eas-cli
eas login
cd nutrimenu-app
eas init                       # привяжет проект, допишет projectId
eas device:create              # зарегистрировать iPhone
```

`eas device:create` даст ссылку или QR — открыть **на телефоне**,
поставить предложенный профиль. Это заменяет кабель и Xcode: так Apple
узнаёт телефон, которому можно ставить сборки.

Дальше сама сборка:

```bash
eas build --profile preview --platform ios
```

EAS спросит Apple ID, сам создаст сертификат и профиль. Через 20–30
минут придёт ссылка — открыть её **в Safari на iPhone**, приложение
встанет по воздуху. Ни кабеля, ни Xcode, ни вашего Mac в этом нет.

Срок жизни такой сборки — год, а не семь дней.

### А потом лучше TestFlight

```bash
eas build --profile production --platform ios
eas submit --profile production --platform ios
```

После этого приложение прилетает в TestFlight: ставится из обычного
приложения Apple, обновляется само, можно раздать кому угодно по
приглашению. Для повседневной проверки это удобнее ссылок, и опять же
без Mac.

### Что по-прежнему требует Xcode

Только одно — симулятор iPhone на компьютере (`development-simulator` в
`eas.json`). На Catalina симулятора с нужной iOS нет, так что этот путь
закрыт. Проверять придётся на живом телефоне, что и так ближе к делу.

## Шаг 1. Подготовить Mac (один раз)

**Нужен Xcode 26 или новее.** На Xcode 16 проект не соберётся: поды
`expo-router` и `@expo/ui` содержат вызовы API из iOS 26
(`UIBarButtonItem.Badge`, `glassEffect`, `hidesSharedBackground`), а с
Xcode 16 идёт SDK iOS 18, где этих имён нет. Проверка
`#available(iOS 26.0, *)` в их коде решает, что выполнится на телефоне,
а не чем собрано: файл компилируется целиком при любой версии, и
компилятор остановится на незнакомом имени. Обойти нельзя — `@expo/ui`
у нас в восьми экранах, `expo-router` — вся навигация.

Если App Store не предлагает обновление Xcode, значит macOS слишком
старая: сначала обновить систему, потом Xcode.

Ещё нужны инструменты командной строки:

```bash
xcode-select --install          # если ещё не стояли
sudo xcodebuild -license accept
```

Открыть Xcode один раз руками, чтобы он доустановил компоненты, и войти
в свой Apple ID: **Xcode → Settings → Accounts → + → Apple ID**.
Платить ничего не нужно, обычная учётка подойдёт.

Проверить Node (нужен 20 или новее) и поставить CocoaPods:

```bash
node -v
sudo gem install cocoapods
```

## Шаг 2. Забрать код

```bash
git clone https://github.com/maximfilippov94/maxim.git
cd maxim
git checkout claude/new-session-9cqu0s
cd nutrimenu-app
npm install
```

Если папка уже есть с прошлого раза — вместо клонирования:

```bash
cd ~/путь/до/maxim
git fetch origin
git reset --hard origin/claude/new-session-9cqu0s
cd nutrimenu-app && npm install
```

## Шаг 3. Создать нативный проект iOS

```bash
npx expo prebuild --platform ios
```

Команда собирает папку `ios/` из `app.json`: разрешения на камеру и
микрофон, значок, заставку, нативную часть видеозвонков. Папка в
репозитории не хранится — создаётся заново на вашей машине.

## Шаг 4. Указать Xcode, кто подписывает

```bash
open ios/EQUA.xcworkspace
```

В Xcode слева выбрать проект **EQUA** → вкладка **Signing &
Capabilities** → цель **EQUA**:

1. Поставить галочку **Automatically manage signing**.
2. В **Team** выбрать свою строку с пометкой **(Personal Team)**.
3. Если Xcode покажет красным «failed to register bundle identifier» —
   поменять **Bundle Identifier** с `ru.equa.app` на свой, например
   `ru.equa.app.maxim`. Значит `ru.equa.app` уже занят в системе Apple.

## Шаг 5. Поставить на телефон

Подключить iPhone кабелем, разблокировать, на вопрос «Доверять этому
компьютеру?» ответить «Доверять». Затем:

```bash
npx expo run:ios --device
```

Команда покажет список устройств — выбрать свой iPhone стрелками и
нажать Enter. Первая сборка идёт 10–20 минут, дальше — 1–2 минуты.

На телефоне приложение откроется и сразу **упадёт с предупреждением о
ненадёжном разработчике**. Это нормально, подпись нужно разрешить:

**Настройки → Основные → VPN и управление устройством → Разработчик
«Apple Development: ваша почта» → Доверять**.

После этого открыть EQUA с домашнего экрана.

## Шаг 6. Как вести работу дальше

Чтобы правки экранов доезжали на телефон без пересборки:

```bash
cd nutrimenu-app && npx expo start --dev-client
```

Mac и iPhone должны быть в одной сети Wi-Fi. В приложении встряхнуть
телефон — откроется меню разработчика, там же «Reload».

Пересобирать через `npx expo run:ios --device` нужно только в двух
случаях: прошло 7 дней, либо в проект добавился новый нативный модуль.

## Если что-то не пошло

| Что видно | Почему | Что сделать |
|---|---|---|
| `Unable to find a destination` | телефон заблокирован или не доверен | разблокировать, переподключить кабель, ответить «Доверять» |
| `No profiles for 'ru.equa.app' were found` | не выбран Team в Xcode | вернуться к шагу 4 |
| `Could not find iPhone` при `expo start` | Mac и телефон в разных сетях | один Wi-Fi, либо `npx expo start --dev-client --tunnel` |
| Приложение открылось, но вход не проходит | нет связи с сервером | проверить, что `nutrimenu.ru` открывается в Safari на телефоне |
| `cannot find 'Badge' in scope`, `has no member 'glassEffect'` | Xcode 16, нужен 26 | обновить Xcode, см. шаг 1 |
| `pod install` падает | старые CocoaPods | `sudo gem install cocoapods && cd ios && pod repo update` |
| Через неделю «Приложение больше недоступно» | истекла бесплатная подпись | повторить шаг 5 |

## Что изменится после оплаты 99 $

Срок подписи вырастает с 7 дней до года, появляются уведомления с
сервера, и сборку можно рассылать через TestFlight — без кабеля и без
Mac у того, кто ставит. Порядок выпуска в магазин описан отдельно, в
`RELEASE.md`.
