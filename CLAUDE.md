# EQUA

Платформа для нутрициологов и их клиентов. Два продукта на одном API:

* **Приложение** — React Native, Expo SDK 57, в этом репозитории: `nutrimenu-app/`.
  Запуск: `cd nutrimenu-app && npx expo start`
* **Веб** — PHP 8 + SQLite + SPA на чистом JS. **В репозитории его нет**, он
  живёт в рабочем каталоге сессии и поставляется архивом `EQUA_public_html.zip`.
  Боевой сайт — nutrimenu.ru.

## Как вести работу

**Сначала обсуждаем, потом делаю.** Порядок для любой задачи, кроме явных
дефектов (см. ниже):

1. Что я понял — задача своими словами.
2. Что там сейчас на самом деле — по замерам, не по памяти.
3. Как предлагаю сделать и почему; если есть выбор — варианты и рекомендация.
4. Чего это коснётся ещё и что проверю после.
5. Вопросы, если без ответа развилка меняет работу.

Разбор короткий: суть, вариант, риск. Не план на страницу.

**Исключение — явные дефекты с единственным решением.** Прислали снимок с
обрезанной подписью, причина — одна строка CSS, вариантов нет: чиню и
докладываю что и почему. Всё, где есть выбор — новая функция, изменение
внешнего вида, поведения, структуры экрана — сначала обсуждаем.

## Постоянные требования

* **Отвечать по-русски.**
* Не переписывать проект с нуля, не заводить отдельный frontend, не подменять
  API mock-данными, не удалять работающие функции.
* Каталог блюд **намеренно высокобелковый** — это не ошибка, не «исправлять».
* `config/mail.php` содержит пароль почты владельца, `config/telegram.php` —
  токен бота Telegram (по нему можно писать от имени бота всем, кто ему
  писал). **Никуда не выкладывать** и не включать в архив поставки.
* После правок в приложении писать команду запуска.

## Проверять машинно, а не на глаз

Причина дефекта часто не там, где он выглядит: кривые значки оказывались
кривыми в рисунке, а не в вёрстке; обрезанные названия — следствием правила
по ширине окна. Поэтому: **замер вместо предположения**, и проверки перед
каждой отправкой.

Проверки веба лежат в рабочем каталоге сессии, запуск единым скриптом:

```
SP=<каталог> sh $SP/check-all.sh
```

Он гоняет три проверки — обрезанный текст, вёрстку, контраст — в трёх ролях
(клиент, специалист, владелец), обеих темах и на четырёх ширинах:
**393 / 1024 / 1440 / 1920**. Ширины не сокращать: пропуск широких окон уже
однажды стоил незамеченной обрезки названий блюд, а 1024 — сломанного левого
края.

Отдельно есть проверка пропорций значков (`icons.js`) — ловит значки,
которые сплющил родитель-флекс.

**Стенд должен быть похож на бой, иначе проверки слепнут.** Пустое поле
на стенде — это экран, который никто не проверял: фотографий блюд в
стендовой базе не было ни у одного из пятидесяти, и по этому замеру я
однажды решил, что их нет и на сайте. Стенд наполняют два скрипта,
оба идемпотентные и в поставку не идущие:

```
SP=<каталог> php $SP/photo-seed.php   # снимки блюдам, шесть пропорций
SP=<каталог> php $SP/stand-seed.php   # всё остальное: аватары клиентов,
                                      # время готовки и теги блюд,
                                      # телефоны, заметки и исключённые
                                      # продукты в карточках, комментарии
                                      # к блюдам, верификация и заметка
                                      # проверяющего, снимки документов,
                                      # записи о звонках в переписке,
                                      # свои блюда у специалиста, бренды
                                      # и порции продуктов, личные
                                      # продукты клиента, заметки тренера
                                      # и в дневнике, видео у упражнения
```

После наполнения пустых у всех строк полей остаётся три, и все три
осознанно: `menu_items.overrides` не читает ни один экран,
`dishes.from_ingredient_id` появляется только через дневник, а
`balance_entries.payout_id` заводит `balance-test` на своих участниках.

Сверка с боем — `db-shape.php` и `db-compare.php`. Первый снимает слепок
формы базы: только имена таблиц и полей и числа, ни одного значения
наружу, поля с паролями и токенами пропускаются вовсе. На боевом
сервере:

```
php db-shape.php > bod.json
```

Рядом со стендом `SP=<каталог> php $SP/db-compare.php bod.json` показывает,
где стенд расходится с боем: не доехавшая миграция, поле заполненное на
бою и пустое на стенде (проверки смотрят не на то) и наоборот. Разницу в
числе строк не показывает — на стенде людей меньше по устройству.

Деньги проверяются отдельно и обязательно: `php $SP/balance-test.php` —
37 сценариев учёта (прошедшие дни, молчание клиента, отказ в выплате,
повторное уведомление эквайера). Он заводит своих участников на стендовой
базе и убирает их за собой. Гонять после любой правки в `balanceAccrue`,
`subPay`, `payoutPick` и маршрутах баланса: на глаз такое не проверяется —
половина сценариев наступает через недели.

Доступ по ролям — так же обязательно: `php $SP/access-test.php` (он же
внутри `check-all.sh`). 59 проверок: каждая роль стучится в каждый раздел
и получает ожидаемый ответ. Гонять после любой правки в `needSection`,
`sectionAccess`, `clientLink` и в маршрутах `/specialist/clients/*`.
«Тренер не видит анализов» — это утверждение о двух десятках маршрутов, и
ломается оно молча: достаточно одной забытой проверки в новом маршруте.

Тренировки — `php $SP/workouts-test.php` (тоже внутри `check-all.sh`).
56 проверок: шаблон, состав, порядок, назначение, выполнение у клиента и
подключение второго специалиста. Гонять после правок в маршрутах
`/specialist/workouts*`, `/specialist/exercises`, `/client/workouts*`,
`/client/sessions/*` и `/client/connect`. Половина этих сценариев —
про то, чего на экране не увидеть: расход по факту, повторное начало
той же тренировки, роль, которая уже занята.

Смена специалиста и деньги при уходе — `php $SP/link-test.php` (тоже
внутри `check-all.sh`). 18 проверок: разрыв связи с обеих сторон,
освобождение роли, потеря доступа, остаток в зачёт и его списание со
следующей оплаты. Гонять после правок в `linkEnd`, `subEnd`,
`clientCreditSpend`, в маршрутах `/client/specialists/*/end`,
`/specialist/clients/*/end`, `/client/connect` и в триггерах
`cs_link_on_client_*`. Тест закрывает два дефекта, каждый из которых
ломался молча: отказ от услуги не освобождал роль (уйти можно было
только к AI), а триггер на `clients.specialist_id` отвязывал тренера
при подключении второго нутрициолога.

Стендовые данные для тренировок ставит `php $SP/wo-seed.php`: тренер
Артём Гурьев, две программы, назначения и история у Анны. Скрипт
идемпотентный и заодно убирает мусор от упавших прогонов тестов.

Для приложения: `npx tsc --noEmit` и сборка бандла
`npx expo export --platform ios`.

## Поставка веба

Архив собирается из каталога сайта. **Не включать**: `_router.php` (только для
локальной разработки), `config/mail.php`, `config/telegram.php`,
`config/legal.php`, `config/payments.php` (ключи эквайера), живую базу
`storage/nutrimenu.sqlite`, ключи `storage/vapid.*`, копии `storage/backups/`
и загрузки `storage/uploads/`. Пустые `storage/` и `storage/uploads/` нужны.

Версию кэша в `sw.js` поднимать при каждой отправке — иначе правки не доедут
до устройств.
